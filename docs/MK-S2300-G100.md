# MK Technology MK S2300-G100 — test report

## Hardware

- Manufacturer: MK Technology
- Product: MK S2300-G100
- USB VID/PID: `1FF7:0013`
- Bus: USB full-speed

## Windows 11 result

The frame was connected to a Windows 11 machine with its video and USB touch connections active. Windows initially routed touch input to the wrong monitor. The mapping was corrected through the classic Tablet PC setup wizard:

```text
rundll32.exe shell32.dll,Control_RunDLL tabletpc.cpl @1
```

After selecting **Touch Input** and tapping the frame's physical display, the browser multitouch test reported ten simultaneous contacts. This is the definitive hardware-side result: the frame can provide 10-point multitouch in its Windows configuration.

## macOS result

On macOS, TouchMyMac receives a stable single-contact stream from the connected device. The physical ten-finger test produced only the short report-ID-`0x01` format; no multi-contact report stream appeared. The app therefore keeps the production path at single touch for now.

The macOS limitation is not evidence that the IR frame lacks multitouch. The Windows result shows the opposite. The remaining question is what Windows or the device firmware does before the multi-contact stream becomes available.

## Evidence collected

- The standard report descriptor exposed by the interface includes a mouse-like report ID `0x01` and a truncated digitizer/vendor section.
- Read-only `GET_DESCRIPTOR` and `GET_REPORT` probes did not reveal a usable multi-contact payload or a documented activation command.
- The captured macOS physical stream contained one-contact report frames only.

## Next investigation

Use a read-only Windows USB capture while comparing these phases:

1. connect the frame before any touch;
2. open the vendor calibration/driver utility, if one is provided;
3. perform a ten-finger gesture;
4. close the utility and repeat the gesture.

Compare control transfers, report descriptors and interrupt reports. Do not replay a command on macOS until its purpose and payload are understood.

## Public-data policy

This report deliberately omits the device serial number, user-specific paths, raw report logs, packet captures and access credentials. Only the non-secret hardware identifiers and reproducible behavior are published.
